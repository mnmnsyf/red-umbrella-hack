## 0. 一句话

**港口出现一艘不明船只时，我们不只说“它可疑”，而是告诉值班员“你还有 04:20 必须做决定”。在那之前，系统先用最温和、仍然来得及的手段替人争取时间，只在真正需要时才把决定交给人。**

---

## 1. 题目理解

- **场景**：凌晨 3 点，港口值班员（harbor watch officer）发现一艘关闭了 AIS 的不明自主/无人船驶向港内。
- **矛盾**：
  - 它可能是威胁，也可能只是故障的船。
  - 一刀切封港代价巨大，等太久又危险。
- **题目真正问的是**：机器到人的交接（handoff）应该发生在哪里、什么时候、以什么形式。物理拦截不在范围内。
- **大赛主题**：要先发制人；找到仍然有效的最温和的应对；要便宜、对人安全，平时也有用（dual-use）。

### 评分维度（每项 1–5 分）及我们的对应

| 维度 | 我们靠什么拿分 |
|---|---|
| Dual-use fit（同分时的决胜项） | 同一个引擎平时就是港口交通管理和避碰工具 |
| Technical execution | 可达集、贝叶斯意图、干预阶梯、注意力调度，外加 500 场景的定量评估 |
| Feasibility & impact | 真实洛杉矶港地图和 AIS 数据、一线从业者访谈、资金路径、成本模型 |
| Adapting to twists | 全部参数化、配置驱动，每个 twist 都能用“改配置 + 一张新图”来回应 |
| Demo / pitch | 倒计时开场、真实语音呼叫、“原来只是坏船”的反转 |

## 2. 四根支柱

1. **核心洞察**：输出的是决策截止时间，不是可疑度分数。
2. **小而硬的算法**：可达集、意图推断和最小充分干预，每一步都可解释。
3. **有温度的故事**：凌晨 3 点的值班员只需要做一个决定；坏掉的船先得到帮助；乘客优先疏导。
4. **别人没有的量化评估**：500 个固定种子场景，和封港、纯人工值守做对比。

## 3. 算法设计

### 3.1 可达集：T_breach，不怕欺骗

- **输入**：目标最后一次可信的位置和航向，船型的最大航速 `v_max` 与最大转向率 `ω_max`（保守取上界）。
- **计算**：目标到达任一保护区的最早时间 `T_breach`。
  - **快速下界**：`T ≥ d / v_max`，`d` 为到保护区的直线距离。
  - **更紧的界**：在 (x, y, heading) 离散状态空间上做多源 Dijkstra 或 fast marching，计入转向约束（近似 Dubins 路径）。
  - 状态空间可以预先算好，以保护区为源反向传播，每帧只需查表。
- **为什么不怕欺骗**：算法只依赖物理上限，不依赖目标自己报告的意图或航线。

**附送的欺骗检测（零额外成本）**
- 若相邻两次上报位置满足 `|p_t − p_{t−1}| > v_max·Δt + ε`，这条轨迹在物理上不可能，判定为 AIS/GPS 被欺骗。
- 欺骗以后，可达集从最后一个可信点继续膨胀，T_breach 只会更保守，不会被骗得更乐观。

### 3.2 意图推断：4 个假设，简单贝叶斯

| 假设 | 典型观测特征 |
|---|---|
| H1 正常通行（transit） | 航向稳定，沿航道，速度正常 |
| H2 徘徊（loiter） | 航向方差大，在小区域里绕圈 |
| H3 故障或漂移（malfunction / drift） | 速度低，航向随风和流漂，对呼叫无回应或回应求助 |
| H4 接近目标（approach asset） | 航向持续指向保护区，接近速度为正，可能加速 |

- 更新：`P(H|o) ∝ P(o|H)·P(H)`。观测包括速度、航向变化、对保护区的接近速度，以及对呼叫的回应。
- 似然用手写的简单分布（高斯或分段函数），参数全部写在配置文件里，便于评委查看，也方便应对 twist。
- **威胁概率** = `P(H4)`，也可以按配置把 `P(H2)` 的一部分算进去。

### 3.3 最小充分干预：每一帧选最温和、仍然来得及的动作

**干预阶梯**

| 等级 | 动作 | 生效时间 e | 侵扰代价 c |
|---|---|---|---|
| L0 | 监视 | 0 | 0 |
| L1 | 呼叫（VHF 或语音 agent） | 约 1 分钟 | 低 |
| L1.5 | 派无人机或无人艇抵近查看（见 3.7） | 拦截 ETA + 约 20 秒 | 低（不影响其他交通） |
| L2 | 疏导附近渡轮和小船改道 | 约 3–5 分钟 | 中 |
| L3 | 电子围栏 + 区域广播 | 约 5 分钟 | 高 |
| L4 | 交给人决定 | t_human | — |

**截止时间**：对每个动作 a，计算

`slack_a = T_breach − e_a − t_human`

**选择规则**：在 `slack_a ≥ 0`（来得及）且能覆盖当前风险的动作中，选侵扰代价 `c_a` 最小的那个。

**交接条件**，满足任一即交接：
- 只剩 L4 还来得及；
- 威胁概率落在不确定区间（如 0.3–0.7，可配置），这时机器不该替人拍板。

**降级**：风险解除（比如目标回应呼叫并改变航向）后，自动回到较低等级。所有动作都可撤销，并写入日志。

### 3.4 告诉值班员什么信息会改变判断

- 对每个即将到来的观测（呼叫是否有回应、是否减速、是否转向），分别算出两种结果下的后验概率。
- 挑出对决策影响最大的一个（某种结果会让推荐的等级发生变化），写成一句话：
  > “若 60 秒内不回应呼叫，威胁概率升至 0.7，建议升级到 L3。”
- 这其实就是一个简化的信息价值（VOI）计算，几行代码就能写完。

### 3.5 注意力调度：把值班员当作稀缺资源

- 同时有多个事件时，每个事件都有自己的交接截止时间 `D_i`。
- 交接顺序按最早截止优先（EDF）排定。
- 若两个截止时间相距小于窗口 W（比如 90 秒），就对其中靠后的那个先启用 L2 或 L3 来拉长它的 `T_breach`，或者把靠前的那个提早交接，确保值班员不会在同一分钟里面对两个决定。
- 这一节也直接回应可能出现的“多船/蜂群” twist。

### 3.6 人的反应时间用实测值

- `t_human` 不写死，用值班员最近几次确认操作的延迟做指数加权平均（EWMA）来估计。
- 值班员越疲劳，`t_human` 越大，系统就越早交接。“凌晨 3 点的疲劳”这件事因此落到了公式里。

### 3.7 抵近查看载具（Sam 的想法）

- **载具**：港内 1 到 2 个基地，各放一台无人机（约 15 m/s）或无人艇（约 10 m/s）。出发准备时间约 30 秒，传感器有效距离约 150 米。均为占位参数，写进 config。
- **拦截 ETA**：沿目标的预测航迹逐秒向后试，找到最早满足 `|target(t) − base| ≤ v·(t − t_launch) + r` 的时间 t。飞行途中每一帧重新计算拦截点（提前量追踪）。
- **派不派**：`ETA + t_assess + t_human ≤ T_breach` 并且威胁概率处于不确定区间时才派；赶不上就直接跳过，进入下一级或交接。
- **模拟摄像头**：到场以后按混淆矩阵给出识别结果（坏船/威胁/正常，准确率约 0.8–0.85，夜间再打折），作为一次强观测代入贝叶斯更新。
- **只查看，不拦截**，符合题目的范围限制。
- **界面**：显示"载具 1:40 后到场 · 决策截止 4:20"。交接卡片里附一张查看画面（演示时用预先准备好的图片）。
- **评估**：增加一组"无载具"消融，衡量载具带来的误报减少和判断准确率提升，并如实报告来不及赶到的场景比例。
- **加分（P2）**：用现成的检测器（如 YOLO）在一张真实船只照片上跑一次。

## 4. 交接界面

一屏一个决定，不超过 5 秒能看懂：

```
┌──────────────────────────────────────────────┐
│  DARK VESSEL #07        决策倒计时  04:20     │
│  最可能：故障漂移 62%  ·  接近目标 21%         │
│  理由：速度 2.1 kn，航向随潮流，60 s 内无回应   │
│  会改变判断的信息：若转向油码头 → 接近目标 70% │
│                                              │
│  [A] 派巡逻艇查看（推荐）                      │
│  [B] 升级围栏 + 广播                          │
│  [C] 继续监视，2 分钟后再问我                  │
│                               [否决系统动作]   │
└──────────────────────────────────────────────┘
```

- 已预填好 VHF 呼叫话术。
- 有一键否决（veto），并保留完整审计日志：系统做了什么、为什么、谁批准的。
- 渡轮乘客的疏导优先级最高。

## 6. 量化评估

- **模拟器**：和演示用的是同一个模拟器的无界面（headless）模式。
- **场景生成器**：每个场景都有已知的真实答案，类型包括良性暗航、徘徊、故障漂移、真实威胁；威胁比例作为参数。用固定种子生成约 500 个场景，所有策略面对的是同一批。
- **对比策略**：
  1. 一刀切封港（blunt shutdown）
  2. 纯人工值守：响应延迟随疲劳增加，参数取保守值并写明
  3. 我们的方法
  4. 消融：把可达集换成直线外推
- **指标**：漏报威胁数、停港分钟数、疏导造成的扰动、误报交接次数、交接时值班员的决策时间。全部给出 bootstrap 95% 置信区间。
- **关键图**：横轴停港时长、纵轴漏报威胁数的散点图，目标是左下角。另有一张威胁比例的敏感性曲线。
- **诚实声明**：这是合成模拟的结果，参数和假设全部公开。

## 10. 技术架构

```
┌──────────────────────┐     WebSocket      ┌─────────────────────────┐
│ Python 引擎（唯一事实来源）│ ─────────────────▶ │ React 前端              │
│ - sim（船舶运动）       │                    │ - 地图（MapLibre/Leaflet）│
│ - reach（可达集 + 欺骗） │ ◀───────────────── │ - 交接界面 + 否决        │
│ - intent（贝叶斯）      │   值班员操作        │ - 倒计时                │
│ - ladder（干预阶梯）    │                    └─────────────────────────┘
│ - scheduler（EDF）     │
│ - config.yaml         │     headless
└──────────┬───────────┘ ─────────────────▶  eval/：场景生成 · 策略 · 指标 · 作图
           │
           └── 可选：Retell 语音呼叫 · AIS 数据回放
```

- 所有参数（阶梯、v_max、似然、阈值、t_human 初值）都放在 `config.yaml` 里。
- **"引擎"指我们自己写的 Python 决策模块，不是 Unity 这类游戏引擎。** 模拟器就是简单的 2D 运动学：每条船是一个点，每个 tick 往前走一步。
- **可视化**：网页 2D 俯视地图，由 Python 通过 WebSocket 每秒推 10 次 JSON 状态。

| 图层 | 实现 |
|---|---|
| 港口底图 | MapLibre + 免费瓦片（如 OpenFreeMap） |
| 保护区 | deck.gl PolygonLayer，半透明红 |
| 船只和航迹 | IconLayer + PathLayer；暗船为橙色 |
| 可达集 | 在到达时间网格上用 `skimage.measure.find_contours` 取 1、2、3 分钟等时线，转成多边形 |
| 查看载具 | IconLayer + 虚线指向拦截点，标出 ETA |
| 倒计时和交接卡片 | React 组件叠加在地图上 |

- 引擎内部单位一律用米。在港口附近，1° 纬度 ≈ 111 km，1° 经度 ≈ 92 km。
- 先定好 JSON 格式。前端用假 JSON 先开工，下午联调时换成真数据。
- 前端赶不上时，用 pygame 或 matplotlib 动画兜底。评估图一律用 matplotlib。
- 演示和评估共用同一套引擎代码，保证评估测的就是演示里的系统。
- 代码全部在题目公布之后编写。
